# 短剧工坊 · 短剧 / 动漫短剧 / 漫剧的剧本与分镜产出系统

一句话：**结构先行，镜头后配，格式定死。**

把"一句话灵感 → 节拍 → 分镜表 → 质检 → 定稿"做成一条可执行、可校验的链路。
纯 Python 标准库，零第三方依赖，不调任何模型——**它不写剧本，它管住剧本的形状**。

## 它解决什么问题

短剧拍砸，八成不是台词写得差，是结构没搭对：

- 前 3 秒没把人钉住，观众划走了
- 四段配比失衡，压力段太短，反转没有铺垫
- 镜数与时长对不上，剪的时候才发现少了 20 秒
- 长镜是空的，演员在画面里没东西可演
- 交付时才发现少了"验收额度"，模型抽到第 8 条还在抽

这些都不是审美问题，是**可以机械检查的**问题。本项目只做机械检查。

## 四种形态

**形态 = 画面从哪来**，与"拍什么题材"无关。换形态就是换媒介，得换尺子。

| 形态 | `--form` | 画面来源 | 对白走 | 有"格" |
|---|---|---|---|---|
| 真人 / AI 写实短剧 | `live_action` | 连续视频 | 配音 / 同期声 | 否 |
| 动漫短剧 | `anime` | 连续动画 | 配音 | 否 |
| 漫剧（动态漫） | `motion_comic` | 静态帧 + 推拉 | 气泡 | 是 |
| 静态漫 / 条漫 | `static_comic` | 静态格，无运镜 | 气泡 | 是 |

形态之外还有**档位**（`--mode`）：`ai` 生成（单镜 3-4 秒最稳）vs `live` 真人实拍
（长镜省机位）。两者**正交**，可自由组合。

```bash
python engine/dramakit.py forms    # 列全部形态与判据差异
```

## 能做什么

| 命令 | 作用 |
|---|---|
| `dramakit new` | 建项目骨架（节拍表 / 分镜表 / 分集表 / 跨集台账） |
| `dramakit plan` | 按配比算四段时长，或排系列分集表；核对平台时长档 |
| `dramakit skel` | 按节拍与核心镜长，算出每段该给几镜，排出空表 |
| `dramakit scan` | 分镜表质检：时长 / 镜数 / 镜头语言 / 钩子密度 / 合规 / 模型上限 |
| `dramakit check` | 交付格式校验：五块结构、列头、验收额度、AIGC 标识 |
| `dramakit continuity` | 跨集一致性对账（连载专用）：时间轴 / 角色 / 场景 / 伏笔 |
| `dramakit forms` | 列出所有形态与判据差异 |
| `dramakit spec` | 查看平台 / 后端规格 |
| `dramakit quality` | 故事质量评分卡：五维结构特征参考分（**不拦稿**） |
| `dramakit progress` | 看项目做到哪一步：哪步做完、产物改没改、下一步干什么 |
| `dramakit selftest` | 106 项回归断言（17 组用例），秒级，不耗 token |

## 不能做什么

- 不生成台词、不生成画面、不抽提示词
- 不管图生视频、TTS、剪辑——这些交外部工具
- 不判断"这个题材行不行"——**题材不行，剧本怎么改都是白改**，那是人的判断
- `quality` 不给"好不好看"下结论。它量的是**结构特征齐不齐**，参考分，不拦稿；
  演技、共情、审美都量不出来，别把它当审稿人

## 快速开始

```bash
cd 短剧工坊

# 环境自检
python engine/dramakit.py doctor

# 立项（真人单集完结）
python engine/dramakit.py new 我的剧 "一句话灵感"

# 立项（漫剧连载，60 集）
python engine/dramakit.py new 我的漫剧 "一句话灵感" --format series --form motion_comic --episodes 60

# 看四段节拍 + 平台时长档
python engine/dramakit.py plan 我的剧 --platform hongguo

# 生成分镜骨架并写入
python engine/dramakit.py skel 我的剧 --write

# 填完动作和台词后质检
python engine/dramakit.py scan 我的剧/分镜表.md --model seedance

# 定稿前校验交付格式
python engine/dramakit.py check 我的剧/我的剧.md

# 连载项目对账
python engine/dramakit.py continuity 我的漫剧

# 任何时候想知道"我做到哪了"
python engine/dramakit.py progress 我的剧
```

## 断点续跑：别拿改之前的结论去交付

中间产物会把错误传下去。改完分镜表之后，上一次 `scan` 的结论就作废了——
但没人记得那是改之前扫的，于是拿着旧结论去交付。

`progress` 用**内容指纹**（sha256，不是 mtime）判断产物有没有变过：

```
  进度 · 我的剧
  ────────────────────────────────────────────────────────
  立项     ✓ 完成  2026-10-20T18:55:40  真人/AI 写实短剧 · single
  分镜骨架   ✓ 完成  2026-10-20T18:55:40  随立项生成
  质检     ! 产物已变更：分镜表.md  2026-10-20T18:55:18  2 阻断 / 4 警告

  下一步  分镜表在上次质检后被改过——重扫：dramakit scan <项目>/分镜表.md --record
```

为什么用指纹不用修改时间：**mtime 会被 checkout、复制、编辑器保存动作改掉**。
只碰 mtime 不算变更，内容真变了才算。

状态存在 `<项目>/.progress.json`（已 gitignore）。`new` / `skel` 自动记，
`scan` 要显式加 `--record`——扫描本身是只读动作，不替你做决定。

```bash
python engine/dramakit.py scan 我的剧/分镜表.md --record
```

增量重扫（`--changed`）**不记进度**：它只重检被改的镜头，全表比例判据是
失效的，记成"质检完成"就是撒谎。

## 写盘前先干跑

写盘不可逆，而错往往不是内容错，是**写到了不该写的地方**（同名项目覆盖、路径拼错）。

```bash
python engine/dramakit.py new 我的剧 "一句话灵感" --dry-run
```

```
  将写入 4 个文件，共 6175 字节
    我的剧\project.json   134 B
    我的剧\README.md   345 B
    我的剧\节拍表.md   1074 B
    我的剧\分镜表.md   4622 B

  干跑：未写盘。确认无误后去掉 --dry-run 再跑一次。
```

`skel` 默认就是干跑（只打印不写），`--write` 才落盘；`--dry-run` 与
`--write` 同用时以干跑为准。`new` 遇到已存在的项目默认拒绝，要 `--force`。

**关于"计费双确认"**：这个说法来自需要付费生成的平台。本项目不调模型、
不产生任何费用，所以"计费"那一半在这里不成立，只吸收"写盘前先干跑"。
不假装有计费，也不假装确认过。

## 两个正交的维度：形态 × 档位

**判据方向是反的，不能共用一把尺子。**

| | AI 生成档 | 真人实拍档 |
|---|---|---|
| 单镜上限 | 8 秒（再长画面崩、动作漂） | 10 秒（没有这个约束） |
| 核心镜长 | 3-4 秒 | 5-10 秒 |
| 核心镜占比 | ≥55% | ≥40% |
| 开场窗口 | 3 秒 | 6 秒 |
| 特写反应镜 | ≤3 秒 | ≤6 秒（演员要时间建立情绪） |

压缩镜头的正确做法不是"每镜都拉长"，而是
**中景长镜承担连续段落，只给信息点留独立短镜**。

切换档位：

```bash
python engine/dramakit.py scan 我的剧/分镜表.md --mode live
```

或在项目 `config/overrides.toml` 里写 `shot_profile = "live"`，之后自动生效。

## 故事质量评分卡（参考分，不拦稿）

`scan` 量镜头语言，量不到"本子有没有戏"。`quality` 补这一维，量五件事：
**事情在发生**（事件密度）、**埋的钉子有人捡**（呼应结构）、**空间在换**、
**不靠旁白点题**、**有人可冲突**。

```bash
python engine/dramakit.py quality 我的剧/我的剧.md
```

```
  总分 92   强  （满分 100；≥80 强，<60 回炉）
  事件密度      25/25  ████████████████████
  呼应结构      25/25  ████████████████████
  空间变化      20/20  ████████████████████
  点题自律      15/15  ████████████████████
  冲突面        7/15  █████████░░░░░░░░░░░
```

**先把话说在前面**：戏好不好最终不可机械判。这里全是代理指标——
爆款短剧反复出现的结构特征。100 分不代表好看，只代表该有的特征都有。

判据细节、四类伪回声的排除规则、已知盲区，见
[`references/quality-rubric.md`](references/quality-rubric.md)。
尺子用 `_test/quality_corpus.json` 的语料证伪：好稿 ≥80、差稿 ≤55、区间不许重叠。

## 判据在哪

全部在 `config/dramakit.toml`。代码里没有硬编码阈值——改一个数，全套判据跟着变。
项目级差异写 `<项目>/config/overrides.toml`，深覆盖全局值，
优先级 **项目覆盖 > 形态 > 档位 > 全局基线**。

## 目录

```
短剧工坊/
├── engine/
│   ├── dramakit.py        # 命令行入口
│   └── lib/
│       ├── common.py      # 常数加载 / 形态档位解析 / 平台模型规格
│       ├── plan.py        # 节拍与分集表
│       ├── shotlist.py    # 分镜骨架 + 交付校验
│       ├── scan.py        # 分镜表质检
│       ├── quality.py     # 故事质量评分卡（五维结构特征）
│       ├── progress.py    # 断点续跑（.progress.json + 内容指纹）
│       ├── continuity.py  # 跨集一致性
│       └── selftest.py    # 回归自检
├── config/dramakit.toml   # 唯一常数表，代码里不写死数字
├── references/            # 结构 / 镜头 / 形态 / 规格 / 交付 / 质量 六份规范
├── projects/              # 一个项目一个目录
│   └── 示例-十七楼/        # 9 镜 61 秒，可直接跑
└── _test/
    ├── quality_corpus.json  # 质量评分卡的证伪语料（好稿/差稿 + 区间）
    └── quality/             # 语料样本本身
```
