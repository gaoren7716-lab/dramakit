# 交付规范

> 定稿只发一个 .md。格式是硬约束，不是建议。

## 一、五块结构

```
## 一、基本信息
## 二、人物表
## 三、场景
## 四、分镜表
## 五、验收额度
```

少一块就不算定稿。序号可写可不写，`dramakit check` 两种都认。

## 二、分镜表列头（按形态两套）

**视频形态**（真人 / AI 写实、动漫短剧）：

```
| 镜 | 时长 | 景别 | 谁在画面 | 动作一句话 | 台词原文 |
```

**漫画形态**（漫剧、静态漫）：

```
| 镜 | 时长 | 景别 | 谁在画面 | 画面一句话 | 气泡对白 |
```

两套不是改名游戏，是两类交付物确实不同：视频要的是"能演的动作"与"台词原文"，
漫画要的是"能画的画面"与"装得下的气泡"。`dramakit check` 按形态取对应列头，
**写错列头等于交错了东西**。

列头各列要求：

- **镜**：阿拉伯数字，从 1 开始，不许跳号
- **时长**：带单位，`6s`
- **景别**：视频形态用影视景别；漫画形态用格（大格/中格/特写格/远景格/插入格）
- **谁在画面**：写人名，不写"他""她"。多个用顿号
- **动作一句话 / 画面一句话**：一句话，写看得见的东西，不写心理活动
- **台词原文 / 气泡对白**：定稿原文。视频形态没有台词写 `—（画面文字：…）`；
  漫画形态的气泡有字数上限，超了装不下

第六列是**原文**，不是摘要。发给制作方之后，台词不会再被改写。

## 三、AIGC 标识（AI 生成必带）

《人工智能生成合成内容标识办法》要求 AI 生成合成内容显式标识。
交付稿的**基本信息块**必须带这一行：

```
- 本片由 AI 生成合成
```

`dramakit check` 会查。真人实拍可关（`dramakit check ... --live-shoot`）。


## 四、场景表（有"格"的形态必须有）

漫剧、静态漫的场景不能只写一句"某地。"——**没登记的场景跨镜会漂，而漂了没人发现**。
必须列成表：

```
| ID | 场景 | 说明 |
|---|---|---|
| S1 | 旧教室 | 靠窗，下午光 |
```

`dramakit check` 对漫画形态会查场景表存不存在。

## 五、人物表要内部自洽

每个人物必须写清三样：外形、服装、贯穿道具。

**服装要对应镜头**：写"镜 1 至 9 同一套"，就要真的每一镜都是那一套。
"谁在画面"里出现过这个人的每一镜，都得在这句话的覆盖范围内。
漏一镜，模型或者剧组就会自己发挥，然后前后不一致。

## 六、验收额度

一行写清两件事：

- 每镜最多重抽（拍）几次
- 失败是停还是继续

例：

```
每镜最多重抽 3 次；失败即停，报我，不自动跳下一镜。
```

没有这一行，制作方会一直抽到满意为止，成本失控；或者抽两条就交，质量失控。

## 七、不要什么

- 不要 CSV（除非对方明确要，那是另一个版本）
- 不要 Word、不要截图
- 不要英文提示词、不要风格后缀
- 不要人物参考图
- 不要给两版剧情让人选

前三条是"别替对方做决定"，后两条是"别把自己的犹豫传出去"。

## 八、校验

```bash
python engine/dramakit.py check 我的剧/我的剧.md
python engine/dramakit.py check 我的漫剧/我的漫剧.md --form motion_comic
```

查四样：五块齐不齐、列头对不对（按形态）、验收额度有没有落数、AIGC 标识在不在。
夹带提示词或风格后缀字样只提醒、不拦——那是风格问题，不是格式问题。
